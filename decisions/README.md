# 公開用の決議記録

現時点でGitHub移行・改定の正式決議記録は未登録です。このテンプレートは承認の証拠ではありません。

正式議事録はNotionに保持し、公開可能な概要を `YYYY-MM-DD-議題.json`（ファイル名は英小文字・数字・ハイフン）に記録します。書式は [`_template.json`](_template.json) を写して使います。`_` で始まるファイルは読み込みません。

- 決議ID、決議日、決議機関、適用条項
- 定足数とその成立、出席者数、賛成・反対・棄権・無効票数
- 判定方法と結果、施行日
- 対象PR、比較元の版、投票対象コミットSHA
- 対象MarkdownのパスとSHA-256（`npm run rules:hash`）
- 原議事録と照合した確認。非公開記録とは決議IDで対応させる

個人名・個人別投票・非公開議事録本文は含めません。集計の公開範囲も確認してください。本文ハッシュに決議ファイル自身を含めないでください。

## 採択済みにする手順

1. 決議記録のJSONを追加する。`documents` には投票対象の文書ごとに、`rules/` からのパス、投票対象コミットの40桁SHA、本文SHA-256を書く。
2. 決議確認担当が原議事録と照合したら `minutesVerified` を `true` にする。
3. `rules/index.json` の対象文書を `"status": "adopted"`、`"decision": "<決議ID>"` にし、`proposal`・`agenda`・`baseCommit` を外す。`date`・`dateLabel` は施行日にする。
4. `note` を採択後の説明に書き換える。

ビルド時に次を確かめ、合わない場合はビルドを失敗させます。

- 決議日が未来でない、施行日が決議日以後、票数の合計が出席者数以下、定足数が不成立なら可決にしない。
- 記録した投票対象コミットの本文のSHA-256が、記録した値と一致する。
- 「採択済み」の文書は、可決かつ議事録照合済みの決議に含まれ、現在の本文のSHA-256が記録と一致する。決議後に本文を変えると公開できません。

ビルドは決議記録の書式と本文の一致だけを確かめます。総会が実際に成立したかは、人が原議事録で確認してください。施行日が未来の決議は「採択済み・施行前」と表示します。
