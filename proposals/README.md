# 改定案

未承認の改定理由・新旧対照・判断事項をここに置きます。ここに記載しただけでは会則になりません。

条文は別PRで `rules/` に差分を出します。対象文書の `rules/index.json` を `proposed` とし、閲覧画面にも「改定案・未承認」と表示します。議決対象の本文を固定し、正式決議後に施行日・決議記録を追加してから適切な表示状態へ移行してください。

定足数・賛成割合・権限の案を、その案自身の承認に適用してはいけません。

## 審議中の案のページ

閲覧サイトの「審議中の案」（`/proposals/`）に、`rules/index.json` で `proposed` の文書を一覧表示します。各文書に次の項目を設定します。

- `proposal`: 理由を書いたこのディレクトリのファイル名（例 `2026-10-09-finance.md`）。同じファイルの文書は1つの案としてまとめて表示します。
- `baseCommit`: 既存文書の改定案で比較元にする版の40桁のコミットSHA。新規の文書には付けません。
- `agenda`: 今回の議決にかける文書は `true`。議決の対象を変えるときに切り替えます。

対象の版と本文SHA-256はビルド時に計算して表示します。議決後は `decisions/` に記録し、文書の状態を移行してから `proposal`・`agenda` を外します。
