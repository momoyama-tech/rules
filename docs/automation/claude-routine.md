# Claude Codeルーチンの運用

対象: 桃山学院大学テック部・momoyama-tech/rules。
案件: https://app.notion.com/p/3f3729af3b7d80e39aa1ebced55ec14d

## 起動方式と承認

承認済みタスクを1回に1件扱うAPI起動用ルーチンを用意する。ルーチン作成とAPI呼出しだけで開発を承認したとは扱わない。対象タスク、仕様版、承認範囲、Putsの実行承認記録と案件relationを最新Notionで照合し、不足すれば調査のみで終了する。

定期確認を併用する場合は頻度・対象をPutsが指定した後に設定し、スケジュール起動では閲覧と差分確認だけを行う。定期処理から開発タスクの選定や起動準備を行わない。変化がなければ通知を抑える。

Notionは読み取り専用。Codeルーチンから仕様、タスク、Schedule、議事録、状態を書き換えない。取得失敗を変更なしと扱わない。未決定の配分率、宿泊上限、予算、承認者、施行日を推測で確定しない。

## 対象と作業

- 対象リポジトリだけをcheckoutし、AGENTS.md・CLAUDE.md・README・仕様・既存PR・CIを読む。重複PRを避ける。
- 承認範囲内でrules/・site/等を編集する。commit・push・Draft PRもその範囲に含まれるときだけ行う。
- `npm run check`、`npm test`、`BASE_PATH=/rules npm run build` と関連UIを検証する。
- 正式決議、本文ハッシュ、レビュー、施行日を区別し、未承認案はproposedと表示する。
- mainへの直接push、マージ、Pages公開、権限・保護ルール変更、外部送信、契約・支払・報酬分配は別の具体的承認を要する。
- 実行結果には対象タスク・仕様・承認照合、PR・commit・CI、検証結果、未確認と判断事項を含める。

## 登録情報

ルーチンURL、実際の起動方式、登録状態はNotion案件に記録する。ルーチンの保存・起動・作業完了は別々に確認する。新しいAPIトークンは発行・保存の確認後、指定されたNotionの「Claude APIトークン」専用欄だけに保存し、README、PR、本文、ログ、チャットに転載しない。このファイルにトークンは保存しない。
